# ping

ICMP Echo Request를 대상 호스트에 보내고 Echo Reply를 받아 **연결 가능 여부와 응답 시간(RTT)** 을 확인하는 도구. 기본 설치되어 있다.

> ICMP를 차단한 방화벽 환경에서는 실제로 통신이 되더라도 ping이 실패할 수 있다.

## 기본 사용법

```bash
ping <호스트 또는 IP>
```

## 주요 옵션

### Linux

| 옵션 | 설명 | 예시 |
|------|------|------|
| `-c <n>` | 패킷 전송 횟수 지정 | `ping -c 4 8.8.8.8` |
| `-i <초>` | 패킷 전송 간격 (기본 1초) | `ping -i 0.2 8.8.8.8` |
| `-s <bytes>` | 패킷 크기 지정 (기본 56바이트) | `ping -s 1400 8.8.8.8` |
| `-t <TTL>` | TTL 값 설정 | `ping -t 64 8.8.8.8` |
| `-W <초>` | 응답 대기 타임아웃 | `ping -W 2 8.8.8.8` |
| `-4` | IPv4 강제 사용 | `ping -4 example.com` |
| `-6` | IPv6 강제 사용 | `ping -6 example.com` |
| `-f` | Flood ping (루트 권한 필요, 부하 테스트) | `sudo ping -f 8.8.8.8` |

### Windows

| 옵션 | 설명 | 예시 |
|------|------|------|
| `-n <n>` | 패킷 전송 횟수 (기본 4회) | `ping -n 10 8.8.8.8` |
| `-t` | 중단(Ctrl+C)할 때까지 계속 전송 | `ping -t 8.8.8.8` |
| `-l <bytes>` | 패킷 크기 지정 | `ping -l 1400 8.8.8.8` |
| `-i <TTL>` | TTL 값 설정 | `ping -i 64 8.8.8.8` |
| `-w <ms>` | 응답 대기 타임아웃(밀리초) | `ping -w 2000 8.8.8.8` |
| `-4` | IPv4 강제 사용 | `ping -4 example.com` |
| `-6` | IPv6 강제 사용 | `ping -6 example.com` |

## 출력 읽기

```
PING 8.8.8.8 (8.8.8.8) 56(84) bytes of data.
64 bytes from 8.8.8.8: icmp_seq=1 ttl=118 time=2.34 ms
64 bytes from 8.8.8.8: icmp_seq=2 ttl=118 time=2.41 ms

--- 8.8.8.8 ping statistics ---
2 packets transmitted, 2 received, 0% packet loss
rtt min/avg/max/mdev = 2.34/2.37/2.41/0.035 ms
```

- `ttl`: 남은 TTL 값. 초기값(64, 128, 255)에서 현재 값을 빼면 대략적인 홉 수를 알 수 있음
- `time`: RTT(Round Trip Time), 낮을수록 좋음
- `packet loss`: 패킷 손실률. 0% 이상이면 네트워크 불안정
- `mdev`: RTT 편차. 클수록 응답 시간이 불규칙함 (jitter)
